# 10 秒连续短片：帧链式延长方法与实测

> 硬件/环境同主 README（RX 6750 GRE 10G · gfx1031 · ROCm 6.2 · ComfyUI 0.37.2 · Wan2.2 TI2V-5B Q4_K_M GGUF）。
> 本文所有数字均为本机实测，测试日期 2026-10-08；与 DeepSeek 的四轮协作分析同步记录。

## TL;DR

- **10.04 秒 = 241 帧 @24fps**。单段上限取 **121 帧**（=5s@24fps，模型原生长度；社区反馈超 121 帧会"回弹首帧"）。
- 结构：`seg1 121帧(T2V) + 续写段(尾帧 I2V) 裁掉尾部退化区后拼接`，每段帧数必须 **4n+1**。
- **接缝几乎不可见**：seg1 尾帧 vs seg2 首帧的逐像素差 **2.1–3.0**，而段内正常相邻帧差是 **12–16** → 衔接处比普通帧间还平滑。
- 单段 121 帧 × 35 步 × 704×480：**19.5–21.8 min**，采样峰值 **9.06G**，零 OOM。
- 三条硬约束（均为实测，非推测）：
  1. **帧数 ≥ 33**。17 帧时模型退化为整帧彩色噪声（三组对照：17帧+任意提示词+18/30 步均崩；33 帧同参数干净）。
  2. **不要让镜头长摇进逆光**。三种结构（2 段/3 段/裁尾短段）的退化都发生在影片位置 ≈7.5–8s 之后，共同点是"摇到亮区后大片高光被烘成辉光"。这是尾部退化的**主因**。
  3. **条件帧必须干净**。用已污染帧做 start_image，下一段第 5–10 帧就开始崩（这是后果放大，不是原因）。

## 工作流（可在网页界面直接改文本）

`workflows/wan22_10s_chain_241f.json` — 拖进 ComfyUI（或放到 `ComfyUI/user/default/workflows/` 后在"工作流"面板点开）：

- 只有**一个主文本框**（① 主提示词）需要改，两段共用（分段续写段与首段文本完全一致）
- 图内自动：取 seg1 尾帧 → 作为 seg2 的 `start_image` → 两段解码 → `ImageFromBatch` 裁掉共享帧 → `BatchImagesNode` 拼成 241 帧 → `CreateVideo(24fps)` → `SaveVideo` 直接出 mp4
- 实测 `BatchImagesNode` 为**按顺序拼接批次**（2+2 帧入 → 4 帧出，已用图内小测试证实）
- 同时保存两段无损 webp，便于后期重剪

## 实测版本对照（尾部退化问题的三轮迭代）

| 版本 | 结构 | 段间接缝像素差 | 结果 |
|---|---|---|---|
| v1 | 121+121−1，原提示词（含"保持句"） | 2.79 | 片头–8s 佳；seg2 从 ~60 帧起过饱和+糊化 |
| v2 | 121+90+30（DS 修订提示词，无"保持句"） | 2.13 / 2.99 | 片头–9s 更锐利；seg2 第 86 帧起头部发白，seg3 因条件帧污染第 5–10 帧即崩 |
| v3 | 复用 v2 素材 + 两段 61 帧（条件帧取干净区） | — | 短段+干净条件帧**不足**：b3 第 20–30 帧又开始发白 |
| v4 | 换抗辉光镜头设计（柔光树荫静态近景）+ 负向压制 flare/bloom | 2.76 / 3.20 / 3.05 | 片头–9s 佳；尾段（新段第 20 帧起）仍糊化 |
| v5 | 每段只取前 35 帧 + 条件帧锁在上一段安全区内 | 2.76 / 3.20 / 1.77 | 接缝全优；但续写段第 20–45 帧仍出现"重影糊化" |

结论（五版实测）：
1. **尾部退化与段长/文本/镜头设计关系弱**；快慢不同、但每个续写段最终都会糊化，可用深度实测在 **20–86 帧**之间浮动（不可预测）。
2. 241 帧（10.04s）的"全链"输出，最后约 0.5–1 秒必然退化 → **要交付干净长片，必须按安全深度裁剪 + 重定时**。
3. 干净素材（本例 175 帧）按 **17.5fps 播放 = 精确 10.000 秒**（运动放慢 27%，不插帧），全程无退化。
   另做跨段饱和度配平（HSV 的 S 通道按平滑增益拉回段首基线：0.70 → 0.66，消除"越来越艳"的观感漂移）。

结论：**尾部退化与段长/文本关系弱，与"镜头是否摇进逆光"关系强**。长摇镜持续 ~8s 后画面出现大片高光，模型把亮部烘成辉光并逐帧扩散。

## 提示词要点（DeepSeek 复审结论，已实测验证有效）

- **续写段用与首段完全相同的文本**。扩散模型看不到"上一帧"，`previous frame` 之类是抽象指令、不起作用甚至干扰；连贯性靠 `start_image` 本身。
- **镜头方向写死**（如 `moving right`），各段一致，避免接缝处方向漂移。
- **避免 `shallow depth of field`**：逐帧虚化不稳定，接缝处反而更明显；用 `slightly blurred background`。
- 负向建议含：`blurry, low quality, deformed, flickering, watermark, text`；抗辉光场景再加 `lens flare, bloom, overexposed, blown highlights, glow, hazy`。
- 抗辉光镜头设计（v4）：柔光树荫静态近景 + 小幅度主体动作（舔爪/尾巴轻摆/草叶微风）+ 极慢推近，避免长摇镜入逆光。

干净区间判定方法（可复用）：逐帧算 **cv2 Laplacian 方差（锐度）** + 近白像素占比（bloom）+ HSV 饱和度，
三曲线一起看，锐度断崖（如本例 f212 从 260 → 45）即为退化起点；起点前的最后一段即安全区间。

## 踩坑补充（接主 README 的 19 条）

- **PyAV 17 的 `container.add_stream("libx264", rate=24.0)` 会抛 `AttributeError: 'float' object has no attribute 'numerator'`**：`rate` 必须传 `Fraction(24,1)`；并给每帧显式 `pts` 与 `time_base`。
- **17 帧不可作为草稿档位**：Wan2.2-5B 在超短长度下整帧彩色噪声，且 `status=success`、亮度指标正常——只看数值会漏掉（必须抽帧人眼验证或加结构性指标）。
- **图片/视频抽帧核验脚本**：`scripts/progress.py` 附带队列阶段识别（按 `SaveAnimatedWEBP` 的 `filename_prefix` 判断当前在跑哪一段）。
