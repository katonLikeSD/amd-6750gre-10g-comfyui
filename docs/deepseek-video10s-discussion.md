# DeepSeek 协作记录：10 秒短片链式延长（2026-10-08/09）

> 与主 README 的 `docs/deepseek-discussion.md`（环境/极限测试三轮）同一个协作线程的延续。
> 本文只记"DS 提了什么、本机实测结果、哪些被推翻、哪些被采纳"，所有结论以本机实测为准。

## 协作方式

ZCode（本机）负责实测与验证，DeepSeek 负责方案设计与社区经验检索；每个结论都标注"已实测"或"需 ZCode 实测"，
被数据推翻的判断**当场回执推翻**（本线程共推翻 3 次，其中 2 次是 DS 自己的建议、1 次是 ZCode 的）。

## 一、方案设计轮（生效）

- 结构：单镜头长运动（不做构图递进），续写段用尾帧像素注入（`Wan22ImageToVideoLatent.start_image`），
  暂装 VideoChunkTools（latent 拼接）——实测证明不需要：接缝像素差 2.1–3.0，段内帧间差 12–16。
- 参数：704×480 / 30–35 步 / cfg 5.0 / dpmpp_2m_sde_heun + sgm_uniform / VAEDecodeTiled 128/32/8/4。**已采纳**。
- "必崩"清单（OOM 后重启、检查残留进程、磁盘余量、pgrep 括号技巧）——**已采纳**。

## 二、提示词复审轮（7 条，全部采纳）

DS 复审并修订提示词：删 `cute`（触发卡通化）、明确镜头方向（`moving right`，两段一致）、
去重复动词（sways→swings）、`shallow depth of field` → `slightly blurred background`（逐帧虚化会闪烁）、
负向精简（distorted 与 deformed 语义重叠留一）、并**撤回自己上一轮的"保持句"建议**：
> "扩散模型没有'上一帧'这个概念……文字里的 previous frame 对它是抽象指令，不起作用，甚至可能让模型困惑。I2V 的连贯性靠的是 start_image 本身，不是文字。"

## 三、被实测推翻的四个判断（按时间顺序）

| # | 原判断（提出方） | 实测反例 | 修正 |
|---|---|---|---|
| 1 | 17 帧草稿可验证提示词（DS 流程） | 17 帧 + 任意提示词 + 18/30 步 → 整帧彩色噪声；33 帧同参数干净 | **帧数 ≥33**；Wan2.2-5B 原生 121 帧 |
| 2 | 裁到 90/30 帧可避开尾漂（ZCode） | 污染从 seg2 第 86 帧就开始了；seg3 从污染帧续写第 5–10 帧即崩 | 条件帧必须取干净区（硬约束） |
| 3 | 短段 + 干净条件帧即可（ZCode） | v3：从干净帧续写、只 61 帧，仍第 20–30 帧发白 | 短段不是充分条件 |
| 4 | 尾漂是"段长/I2V 累积误差"（ZCode，DS 曾认同） | v1/v2/v3 退化都落在影片位置 ≈7.5–8s 之后，与段边界无关 | **主因是镜头设计（长摇镜摇进逆光，大片高光被烘成辉光）** |

## 四、DS 给的回退顺序（已部分采纳为判据）

1. 先压段长 → 2. 再试 spmix（I2V 特化融合版）→ 3. 最后上 FreeLong 类工具。
本机按此顺序执行到第 1 步后发现主因不在段长，改为修镜头设计（v4）；spmix 对照版列为备选。

## 五、v4 生效设计（抗辉光镜头）

柔光树荫静态近景（小动作承载：尾巴轻摆/草叶微风，极慢推近）+ 负向显式加
`lens flare, bloom, overexposed, blown highlights, glow, hazy`。
实测：seg1 全 121 帧 bloom 0.3–2.0、饱和度 0.62–0.73 无爬升（对比 v1–v3 尾部 bloom 爬到 2.5–4.6 且目视霓虹化）。

## 六、方法级教训（写给复现者）

- `status=success` 与亮度指标都不可信：17 帧崩坏时两者全部"正常"。**必须抽帧人眼验证**。
- 视频级质量需要**逐帧指标曲线**（bloom=近白像素占比、饱和度、Laplacian 锐度）定位退化起点，单看首尾帧会漏。
- 每段物料的"可用深度"随内容变化（本例 20–86 帧），做链式延长时必须按曲线裁尾，而不是按固定帧数。
