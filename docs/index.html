关键实测结论

接缝链式续写段的接缝像素差 1.4–3.2，段内正常帧间差 12–16 → 衔接比普通帧间更平滑。

硬约束帧数 ≥33（17 帧必崩成彩色噪声）；续写段可用深度仅 20–86 帧且浮动； 241 帧全链最后约 0.5–1 秒会糊化 → 干净成片需按锐度曲线裁尾 + 重定时。

可用GGUF 底模可直接挂 LoRA（实测复现官方 Turbo 合并模型效果，锐度 −15%）。

4 步必挂 LoRAspmix 走 4 步时 必须挂 Turbo LoRA：锐度是不挂的 5–10 倍（119–172 vs 13–27）；4 步裸跑只是欠去噪的软图。

闪烁固定镜头静止场景的帧间差中位 4.8–7.5；LoRA 版更锐但更"AI 光泽"。缓解手段：shift=3 + 时域平滑（推荐配置见下）。"关 LoRA"以软换稳，实测被平滑方案在两条轴上全面压过。属缓解而非根治，如实标注。

闪烁推荐配置LoRA 1.0 + ModelSamplingSD3 shift=3 + TemporalSmoothingLite(k5, σ1.0, strength 0.5) —— 实测 抖动 4.29 / 锐度 37，全面优于"不挂 LoRA"（4.81 / 27）。强度曲线：0.3 抖 −15%（最保锐度）｜0.5 抖 −24%｜0.7 抖 −33%｜1.0 抖 −46%（锐度同步下降，属硬权衡）。详见 docs/flicker-fix-test.md

解码4 步档下瓶颈转为 VAE 瓦片解码（~2.5 s/帧 @480p，~5 s/帧 @720p）。

Hummingbird-XTAMD 官方，Wan2.2-5B 蒸馏 + 轻量 VAE（解码 14×/显存 4×）；官方目标 RDNA4，本机 RDNA2 属未支持配置，主权重 9.5GB 放不下 → 仅轻量 VAE 值得移植。详见 docs/hummingbird-xt-eval.md

可用10G 显存跑 21GB INT8 主模型（convrot_w4a4 原生内核）+ 15.7GB 文本编码器：需 D 盘 124 GB 页面文件 + HSA_OVERRIDE_GFX_VERSION=10.3.0（RDNA2 必需）

甜点分辨率是最大杠杆，但上限 ≈ 576×320；864×480 直接跌入"权重逐层重载"抖动区（~13 min/步）。4 步 LoRA 相对 6 步 1.52×（步数减半、单步 47.8 s 变慢，净提速）

踩坑博主工作流 JSON 存在共享 link 序列化缺陷（BasicScheduler.model / VAEDecodeAudio.samples 断线 → Required input is missing），已全部修复并附修复方法

编码SaveVideo 改 mp4 + h264 + re-encode + crf 14（默认 auto 约 0.85 Mbps，糊感一部分来自编码）

SeedVR2 视频原生超分（2026-10-15 深夜）：ByteDance SeedVR2 3B（Q8 GGUF + BlockSwap=32 + 256 瓦片）在 10G 卡跑通，1052×640 输出质量全场最自然（生成式重建皮肤/发丝/蕾丝）；默认参数会 OOM（单次申请 9.1GB），保守参数单条 34 分钟。

画质流水线（2026-10-15 晚）：超分（UltraSharp/Remacri/x4plus 三模型对比）→ 时域EMA防抖（帧间差 1.68→1.33）→ RIFE 插帧 48fps；先防抖再超分（超分放大帧间噪声）；提示词"locked-off + Pre-Act Lead-In"可额外降抖 11%；构图=免费分辨率（特写脸 200px vs 全身 60px）。SeedVR2 3B 视频原生超分已本地化中。
